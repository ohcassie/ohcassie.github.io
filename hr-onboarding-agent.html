DWG-01 · Site Survey

Onboarding quality was a function of which manager you got

None of the pieces were missing. There was a checklist, an IT ticket, a benefits deadline, an orientation deck. The problem was that all of it lived in different places, got handed to a brand-new manager to orchestrate on top of their normal job, and depended entirely on that manager remembering to run it well.

Some new hires got a great first 90 days: a clear plan, regular check-ins, a manager who knew what to prompt and when. Others got a laptop, a login, and silence until their first 1x1. Same company, same offer letter, wildly different experience, and HR only found out which one happened when a new hire was already disengaged or already gone.

01

Pre-Day-1 logistics (paperwork, IT setup, what to expect) sat scattered across systems, so a new hire's first real interaction was often confusion, not welcome.

02

Onboarding quality rode entirely on the assigned manager's bandwidth and experience, with no consistent floor underneath a first-time manager or an overloaded one.

03

New hires were flooded with information in week one, then left largely on their own past that, right when role-specific questions actually start showing up.

04

The HR team fielded the same repetitive questions, badge access, benefits enrollment windows, where to find a policy, for every single new hire class.

DWG-06 · Success Signals

What tells us it's working

This hasn't run a full onboarding cycle yet, so there's no adoption number to point to. These are the signals the pilot is designed to move, and the ones that will decide whether it scales past the first cohort.

01

30/60/90 check-ins actually happen, on time, for every new hire, regardless of how experienced or busy their manager is.

02

Repetitive logistics tickets to HR drop for the questions the agent is built to answer directly, freeing the team for the questions that need a real person.

03

New hire pulse survey scores at day 30 and day 90 stop varying so widely by manager, showing the experience has a consistent floor under it.

DWG-07 · Sign-Off

Where it stands

The design is complete and scoped for a pilot rather than an enterprise-wide launch, following the same playbook that worked for the earlier Copilot Studio bots: prove it narrow before going broad.

NOW

Build against the four pillars

Stand up the agent in Copilot Studio using the same platform and lessons learned from the development, HR FAQ, and new manager bots already live.

NEXT

Pilot with the next new hire class

Run it end to end with one incoming cohort and their managers before opening it up further, and gather feedback from both sides.

THEN

Check the success signals

Look at check-in completion, ticket volume, and pulse survey variance from the pilot cohort before deciding how far to roll it out.

SCALE

Open it to every new hire

If the pilot moves the signals it's meant to, extend it org-wide as the default onboarding experience, not an optional add-on.
