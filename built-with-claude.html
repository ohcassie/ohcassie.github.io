DWG-01 · Site Survey

The idea was never the bottleneck. Building it was.

HR leaders are usually good at spotting the actual problem: the process that's quietly broken, the review that inflates every rating, the onboarding experience that depends on luck. What's rare is the ability to go from that diagnosis to a working, testable thing without handing it to someone else and waiting.

That gap is normally where good ideas go to die, not because they're wrong, but because they sit in a backlog behind work that has an engineer already assigned to it. Every page on this site, including this one, exists because that gap closed. The problem got described in plain language, in a conversation, and came out the other side as a real, working page the same day.

DWG-02 · Structural Plan

How each case study actually gets built

The same four steps, every time, whether it's a rating framework or an AI agent.

01

Bring the real problem, not a spec

Describe the actual pain point the way you'd explain it to a peer over coffee, not as a formal set of requirements. The messiness is useful information.

02

Work through the structure together

Claude proposes a framework or a set of pillars; it gets pushed back on, reshaped, and refined in conversation until it actually reflects the real tradeoffs.

03

Get a working demo, not a mockup

Every interactive piece on this site, click-to-expand pillars, sample conversations, the reasoning trace, is real, functioning code, not a static image of what it might look like.

04

Test it like a real feature

Open it in an actual browser, click through every interaction, fix what's broken, then ship it. Nothing goes live untested, even on a portfolio site.
